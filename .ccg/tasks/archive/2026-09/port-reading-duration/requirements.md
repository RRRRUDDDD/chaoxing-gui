真实页面证据：该附件 type=read / module=insertread，任务页列出三本专题书籍，要求阅读总时长 60 分钟，页面提示当天阅读时长次日更新。普通 PPT 不属于这个任务。现有 study_read/readv2 只完成任务点，不用于本功能。

采用原创的后台阅读上报服务，直接按原网页 logs.js 的协议执行：登录账号的课程卡片 → api/work?type=read → coursedata/job/show → 关联书籍 course/zt 页面 → 每 5 秒 multimedia/readlog。携带原链接 _from_ / _fromV2_ 归属信息和实际书籍章节。真实无窗口浏览器已验证每次滚动产生该请求，响应 HTTP 200 + {}。无需 pyautogui、额外浏览器或 Node 运行时，不接管鼠标。

UI 继续使用选课 → 读取列表 → 勾选阅读任务 → 设定每个任务新增分钟 → 开始/查看进度/停止。列表展示章节、平台现有分钟、要求分钟及书籍数。支持 0.1–1440 分钟（默认 30），按真实经过的时间运行，不加速时间。功能名 reading_time，复用 catalog 和现有 HTTP/IPC 起停。

进度的秒数仅代表按真实间隔成功发送的阅读记录时长，不等同于平台最终计分。结果分别展示上报时长和平台开始/结束统计；平台不提供即时变化时明确提示可能次日更新，不报已达标。登录失效、非法/空响应、业务拒绝、无可读内容、网络失败均报错；GET 上报禁用自动重试。停止保留已发送记录；退出后不自动重放 reading_time。
